# Internationalization (i18n)

Suzume Design ships **19 locales**. Every locale file also loads the matching
`dayjs` locale.

```tsx
import { ConfigProvider } from '@suzume-design/web-react';
import zhCN from '@suzume-design/web-react/es/locale/zh-CN';

<ConfigProvider locale={zhCN}>
  <App />
</ConfigProvider>;
```

## Switching language at runtime

```tsx
'use client';
import { useState } from 'react';
import { ConfigProvider, Button } from '@suzume-design/web-react';
import zhCN from '@suzume-design/web-react/es/locale/zh-CN';
import enUS from '@suzume-design/web-react/es/locale/en-US';

const LOCALES = { 'zh-CN': zhCN, 'en-US': enUS } as const;

export function Providers({ children }: { children: React.ReactNode }) {
  const [lang, setLang] = useState<keyof typeof LOCALES>('en-US');
  return (
    <ConfigProvider locale={LOCALES[lang]}>
      <Button onClick={() => setLang(lang === 'en-US' ? 'zh-CN' : 'en-US')}>
        {lang === 'en-US' ? '中文' : 'English'}
      </Button>
      {children}
    </ConfigProvider>
  );
}
```

Components read the locale from context and re-render automatically.

## Overriding individual strings

```tsx
<ConfigProvider
  locale={enUS}
  componentConfig={{
    Modal: { okText: 'Confirm', cancelText: 'Back' },
    Upload: { uploadText: 'Choose file' },
    Empty: { description: 'Nothing here yet' },
  }}
>
```

`componentConfig` sets **default props** for a component everywhere it is
rendered. For copy that only exists inside a locale dictionary (pagination
labels, date-picker shortcuts, table "expand" text), extend the locale object
instead:

```ts
const myLocale = {
  ...enUS,
  Pagination: { ...enUS.Pagination, jumpTo: 'Jump to' },
};
```

## Building the locale dictionary yourself

```ts
import type { Locale } from '@suzume-design/web-react';

const myLocale: Locale = {
  locale: 'en-US',
  Pagination: { page: 'Page', jumpTo: 'Go to', total: ({ total }) => `of ${total}` },
  // ...
};
```

## Dates

Components use **dayjs**, not moment. Every locale file imports its dayjs
locale, so `DatePicker`, `RangePicker`, `TimePicker`, `Calendar` and
`Statistic` follow the configured language automatically.

```tsx
import dayjs from 'dayjs';
import 'dayjs/locale/zh-cn';

dayjs.locale('zh-cn'); // app-level date formatting outside the components
```

## Direction

RTL layouts are driven by the `ConfigProvider` `rtl` prop; component styles
ship `-rtl` modifiers (`suzume-btn-rtl`, ...).

## SSR

Persist the chosen language in a cookie or the URL and read it in your root
layout, so the server renders the same locale the client hydrates with.
`ConfigProvider` only affects render output - no browser APIs are used - so it
is safe to render on the server.
